# API 与数据访问规则

## API 契约

- 请求和响应字段使用 lowerCamelCase；日期时间使用 ISO-8601 字符串，时间语义和时区必须明确。
- ID 使用 `Long` 或字符串时，前后端必须确认 JSON 精度与序列化策略；不要悄然改变已发布字段类型。
- 成功响应、业务错误和校验错误应遵循同一种项目响应结构。新增接口不得自创一套包装格式。
- 修改字段含义、枚举值、必填性或错误码属于兼容性变更；在未评估调用方前不得直接替换。

## MyBatis-Plus 与 MySQL

- 所有查询必须显式选择需要的列，禁止把 `select *` 当作默认写法。
- 所有动态条件都必须参数化；禁止 `${}` 拼接来自请求、配置或数据库的数据。
- 列表查询必须指定排序，筛选和排序字段应有相应索引支撑。大数据量查询必须分页或分批处理。
- 更新和删除必须有明确条件；更新前检查影响范围，避免空条件批量操作。
- 数据库层保留唯一性、非空、外键/逻辑关联和索引等完整性约束；应用层校验不能替代数据库约束。
- Entity 字段与表字段映射必须显式、可读；审计字段、逻辑删除和乐观锁规则在同一业务域内保持一致。
- 事务内不得执行不必要的远程调用或长耗时操作，避免锁持有时间失控。
