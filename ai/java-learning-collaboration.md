# Java 学习阶段协作约定

## 实现原则

- 开发者处于 Java 学习阶段。生成或修改代码时，优先采用 Java、Spring 官方文档和主流社区广泛接受的实践；不要为炫技引入冷门技巧、过度抽象或不必要的框架能力。
- 优先写清晰、直白、易调试的实现。使用语言特性、设计模式或框架能力前，先确认它能解决当前问题；存在同样可靠的简单写法时，选择简单写法。
- 新增代码尽量使用明确的类型、命名和控制流，避免将多层逻辑压缩成难以阅读的链式调用。每个公共方法和非显然的私有方法都应有足以帮助理解的说明。

## 代码注释与说明

- 对初学者不直观的内容补充准确、紧贴代码的注释或说明：类职责、字段业务含义、方法的输入输出与边界、泛型、集合操作、异常处理、事务、校验和序列化。
- 使用注解时，说明该注解在当前位置的实际作用和生效范围；例如它影响的是类、字段、方法还是参数，以及由谁在何时处理。显而易见的简单注解可在同一类或同一模式首次出现处集中说明。
- 注释解释意图、约束或原因，不机械复述赋值、getter/setter 或 Java 语法。字段注释、Javadoc 和单行注释格式仍以 `ai/rules/java-code-style.md` 为准。

## 交付与风险说明

- 交付时，除“改了什么”外，还要简要说明关键代码为什么这样写，包括类职责、调用链、重要变量、参数与返回值、异常处理和数据流。无法从项目确认的信息必须明确说明，不能将推测写成事实。
- 多个合理方案并存时，说明推荐方案和取舍。涉及 API、数据库、并发、安全、事务或兼容性时，指出风险与验证方式，不能只给出能编译的代码。
- 修复错误时，先说明根因、影响范围和触发条件，再提供最小且符合规范的改动；同时补充或建议相应测试。
- 除非用户明确要求只要结论或只要代码，回答使用中文；代码标识符、标准 API 名称和必要技术术语保留原文。
