# 开发工作流

1. 阅读 `agent.md`、相关规则和现有实现；确认需求、兼容边界及受影响模块。
2. 先设计接口、错误处理、数据约束和事务边界，再实现最小完整改动。
3. 为新规则或缺陷补充合适层级的测试；不要用全量启动掩盖缺少单元测试的问题。
4. 按风险执行验证：文档改动检查链接和 Markdown；局部 Java 改动运行 `./mvnw validate` 与针对性测试；依赖、配置、跨模块或数据库改动再执行 `./mvnw test` 或构建验证。格式问题用 `./mvnw spotless:apply` 修复，不能手工猜格式。
5. 查看 `git diff` 与 `git diff --staged`，确认没有凭据、调试代码、无关格式化或生成物。
6. 使用 Conventional Commits 提交；钩子失败时修复根因，不用 `--no-verify` 绕过。
