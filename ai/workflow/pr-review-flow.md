# PR 审查与预检流程

## 本地提交

- `commit-msg` 钩子执行 Commitlint，格式不符合 Conventional Commits 时阻止提交。
- `pre-commit` 钩子执行 `./mvnw validate`：Spotless 检查格式，Checkstyle 检查 import、空白、文件结构和基础 Java 风格。格式失败时运行 `./mvnw spotless:apply`。
- Java 改动至少应执行对应测试；提交前检查格式、编译错误、未使用 import、调试输出和敏感配置。
- 小改动优先运行影响范围最小的检查；依赖、构建、跨模块、数据库或配置变更必须提高验证等级。

## 审查清单

- 业务逻辑是否放在正确层级，事务边界是否明确？
- 参数、权限、空值、分页和并发冲突是否被验证？
- API、状态枚举、数据库约束和前端调用是否保持兼容？
- 是否引入 N+1 查询、无界查询、全表更新/删除、SQL 拼接或敏感日志？
- 是否有可复现的测试，且失败信息足以定位问题？
- 提交是否聚焦、可回滚且通过 Commitlint？

CI 应至少执行测试和提交信息校验；后续接入静态分析或覆盖率门禁时，阈值必须基于项目实际基线制定，不能凭空设定数字。
